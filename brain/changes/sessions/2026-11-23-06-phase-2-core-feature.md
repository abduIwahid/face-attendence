"Try again" remounts the camera for a fresh attempt.
  - **POST /api/verify — server re-checks everything.** Rate limit 10/roll/10 min; loads the student + stored descriptor via service role; computes the euclidean face distance server-side (ADR-008) against the ADR-006 threshold (0.6, strict); haversine via `lib/geo.ts` against `class_settings`; GPS accuracy cap 50 m; duplicate check against today's PRESENT row (Asia/Karachi server date) with the DB partial unique index as the race backstop (23505 → ALREADY_MARKED). The ordered decision is a pure function, `lib/verify.ts` `decideVerifyOutcome`. PRESENT and FAILED (face mismatch / too far) attempts are written to `attendance` with face_match, distance_meters, gps_accuracy_meters and failure_reason; GPS_INACCURATE writes no row (a fix that rough is not evidence — SECURITY.md). Missing class location → 422 CLASS_LOCATION_NOT_SET in plain language.

- **Decisions + reasoning:**
  - **ADR-007** — rate limiting storage: in-memory fixed-window counters (limits per API_SPEC; per-instance on serverless, accepted for v1; Supabase counter table is the upgrade path).
  - **ADR-008** — package = @vladmandic/face-api (maintained fork); verify match decided server-side (API_SPEC's stated v1 default / ARCHITECTURE hardening path), superseding ADR-002's browser-decided match for the decision itself; descriptor endpoint not built.
  - **Match boundary:** distance strictly below 0.6 matches (face-api's own FaceMatcher semantics); pinned by tests.
  - **Photo retention:** implemented as DATA_MODEL specifies (photo stored in the private bucket at registration). The descriptor-only alternative stays an open decision (ETHICS_PRIVACY / CUT LIST item 3) — nothing about retention policy changed.
- **Problems + fixes:**

Deployed instead via the Vercel REST API with binary digest uploads using the custom.vercel-api vault credential — same project, same production target, verified READY + live checks.
