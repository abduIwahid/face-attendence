## Phase 3 — what was built

- **GET /api/log?date=YYYY-MM-DD** (API_SPEC's spec, finally built). Teacher session required (401 UNAUTHORIZED otherwise); the read runs through the teacher's **session client under the existing RLS teacher-read policies** — no service role for display data (DATA_MODEL.md). Defaults to today (Asia/Karachi); the date is validated as a real calendar date (`logDateSchema` + `lib/dates.ts`). Rows are shaped by the pure `lib/log.ts` (student join, Karachi time formatting) into `{ name, roll_number, date, time, face_match, distance_meters, gps_accuracy_meters, status, failure_reason }`.
- **Teacher attendance log UI** (`components/AttendanceLog.tsx`, on /teacher): date picker + Today shortcut (default today, Asia/Karachi), present/failed/total summary counts, and the DESIGN.md table — Time, Name, Roll Number, Face Match, Distance (always with unit, "—" when none), Result (PRESENT success / FAILED danger + the plain-English reason). States: skeleton rows while loading, honest empty state, error state with retry. The table scrolls inside its own `overflow-x-auto` region (min-width 640 px) so the page never overflows.
- **Excel export** — SheetJS `xlsx` 0.18.5 (the PRD/API_SPEC-planned dependency; installed in Phase 3, before the 75% dependency freeze). The Download .xlsx button builds the workbook client-side from the exact rows on screen (`lib/exportXlsx.ts` over `lib/log.ts`'s PRD columns: Date, Time, Name, Roll Number, Face Match, Distance (m), Result), filename `attendance-YYYY-MM-DD.xlsx`, column widths set. SheetJS is dynamically imported on click so the teacher page's first paint stays light. **Verified by round-trip unit test:** the generated workbook parses back with headers and values intact (distance stays numeric).
- **Registered-students view + deletion path** (`components/StudentsList.tsx` + GET/DELETE /api/students). GET: teacher session, RLS read, names/roll numbers/registration dates only — descriptors never leave the server. DELETE: teacher session, then service-role writes (RLS grants the teacher reads only) implementing ETHICS_PRIVACY principle 4 as **real deletion**: registration photo removed from the private bucket first (a storage failure aborts with nothing half-deleted), then the student's attendance rows, then the student row (descriptor included). The UI uses a two-step confirm that states plainly what will be permanently removed.
- **Full settings page** — `/teacher/settings`: hosts the full ClassLocationSettings control (class name, sampled GPS capture, radius) plus a "How the check uses these settings" card explaining the ADR-009 semantics in plain English. The dashboard keeps the same control (same component, same row) — nothing about the Phase 2 setter broke. `GET /api/class-settings` now also returns `updated_at`, and the control shows "Last saved …" (Karachi time). Teacher nav (Dashboard / Class settings, DESIGN.md active state) added to the teacher header.
- **Failed-attempt logging** (Phase 3 SHOULD item): already shipped in Phase 2 (session 06) — PRESENT and FAILED rows are written by /api/verify; Phase 3's log is what makes them visible. Checkbox ticked on that basis.

## Decisions + reasoning

- **ADR-010** — the frontend pass: DESIGN.md palette/fonts applied as a complete system instead of replaced; landing structure; the globals.css motion layer; the responsive method; the reference material reused.
- **Log reads via the session client, not the admin client** — the task brief and DATA_MODEL agree: teacher display data goes through RLS. (lib/supabase/admin.ts's header comment said "teacher log reads" used the service role — stale Phase 2 wording, corrected in this session; comment only, no behaviour change.)
- **Student deletion ordering** — photo first, then attendance rows, then the student row: any failure aborts before the record is half-deleted, and the FK (attendance → students, no cascade in the schema) is respected.
